# NFR 要件（ユニット ec-app）

## 1. ユーザー体験（UX）

| ID | 要件 | 検証方法 |
| --- | --- | --- |
| UX-01 | 一覧からカート追加、カートから購入手続きまで、それぞれ 1 クリックで到達できる | E2E テスト |
| UX-02 | 操作結果は 300ms 以内に視覚的フィードバック（トースト・バッジ更新・ボタン状態）を返す | 目視／E2E |
| UX-03 | データ取得中はレイアウトの崩れないスケルトンを表示する | 目視 |
| UX-04 | 空状態（検索結果なし・カート空）には次の行動への導線を置く | E2E テスト |
| UX-05 | フォームのエラーは項目の直下に表示し、送信時は最初のエラー項目にフォーカスする | E2E テスト |
| UX-06 | 送料無料までの残額をプログレスバーで可視化する | ユニット／E2E テスト |
| UX-07 | 入力補助: `autocomplete` 属性、`inputmode` 属性を適切に設定する | コードレビュー |
| UX-08 | `prefers-reduced-motion` が有効な場合はアニメーションを抑制する | コードレビュー |

## 2. アクセシビリティ

| ID | 要件 |
| --- | --- |
| A11Y-01 | すべての操作がキーボードで可能で、フォーカスリングが視認できる |
| A11Y-02 | 「本文へスキップ」リンクを設ける |
| A11Y-03 | フォーム項目には `<label>` を関連付け、エラーは `aria-invalid` と `aria-describedby` で紐付ける |
| A11Y-04 | トーストは `role="status"`（`aria-live="polite"`）で読み上げられる |
| A11Y-05 | アイコンのみのボタンには `aria-label` を付ける |
| A11Y-06 | 本文テキストのコントラスト比は 4.5:1 以上 |

## 3. 性能

| ID | 要件 |
| --- | --- |
| PERF-01 | ローカル環境で API の応答は 100ms 以内 |
| PERF-02 | 商品データはセッション内でキャッシュし、画面遷移ごとに再取得しない |
| PERF-03 | 外部 CDN・画像に依存しない（商品ビジュアルは絵文字＋グラデーション） |

## 4. セキュリティ・信頼性

| ID | 要件 |
| --- | --- |
| SEC-01 | 注文 API はリクエストボディを検証し、不正な入力には 400 を返す |
| SEC-02 | 価格・合計はサーバー側で計算する |
| SEC-03 | ユーザー入力は React のエスケープに任せ、`dangerouslySetInnerHTML` を使わない |
| REL-01 | 在庫不足時は在庫を一切減らさない（全件検証後に引当） |

## 5. 保守性・実行容易性

| ID | 要件 |
| --- | --- |
| MNT-01 | TypeScript strict モード、`npm run typecheck` がエラー 0 件 |
| MNT-02 | 共有ロジック・API はユニットテストでカバーする（Vitest） |
| MNT-03 | 主要な購入フローを E2E テストでカバーする（Playwright） |
| RUN-01 | Node.js 20 以上で `npm install` → `npm run dev` により起動できる |

## 6. 技術スタック

| 区分 | 採用技術 |
| --- | --- |
| 言語 | TypeScript |
| フロントエンド | React 19, React Router 7, Vite |
| API | Hono + @hono/node-server |
| テスト | Vitest, Playwright |
| スタイル | 素の CSS（CSS カスタムプロパティによるデザイントークン、ダークモード対応） |

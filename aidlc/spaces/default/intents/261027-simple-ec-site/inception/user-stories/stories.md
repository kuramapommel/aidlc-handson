# ユーザーストーリー

- ペルソナ: **P1 高橋 遥**（`personas.md`）。以下「遥さん」と書く。
- まとめ方: 利用の流れ（探す → 日程を選ぶ → 購入する → チケットを確認する）に沿う。利用資格は最後のグループにまとめる。
- 粒度: 1 ストーリー = 1 つの振る舞い。
- 優先度: MoSCoW。最終的な MVP の線引きは後の工程で決める。
- 受け入れ基準は Given/When/Then 形式で書く。要件 ID は `requirements.md` のもの。

## US1. 探す

### US1.1 一覧で全体を見渡す

- **ストーリー**: 遥さんとして、社内ポータルから開いた画面で研修コースの一覧を見たい。どんな研修があり、いつ受けられるのかを最初に把握したいからだ。
- **優先度**: Must Have
- **要件**: FR1.1, FR2.1, FR2.7, NFR1, NFR4
- **依存**: なし

受け入れ基準:

- **AC1.1.1** Given 遥さんが社内ポータルからサイトを開いた, When 最初の画面が表示される, Then ログイン画面を経ずにコース一覧が表示され、ヘッダーに遥さんの名前が表示される
- **AC1.1.2** Given コース一覧が表示されている, When 各コースの表示を見る, Then コース名・カテゴリ・概要・受講料（pt）・直近の開催日・空席のある日程の数が表示されている
- **AC1.1.3** Given コース一覧が表示されている, When 件数表示を見る, Then 表示中のコースの件数が表示されている
- **AC1.1.4** Given コースのデータを読み込んでいる最中, When 画面を見る, Then 読み込み中であることが分かる表示になっており、0 件の表示とは区別できる

INVEST: 一覧表示だけで価値が完結し、他ストーリーに依存しない。

### US1.2 キーワードで探す

- **ストーリー**: 遥さんとして、「AI」「入門」のような言葉でコースを絞り込みたい。専門用語の多い一覧から、初心者向けのコースをすぐに見つけたいからだ。
- **優先度**: Must Have
- **要件**: FR2.2, NFR1
- **依存**: US1.1

受け入れ基準:

- **AC1.2.1** Given コース一覧が表示されている, When キーワード欄に「AI」と入力する, Then コース名または概要に「AI」を含むコースだけが表示され、件数表示も更新される
- **AC1.2.2** Given コース一覧が表示されている, When 「AI　入門」（全角スペース区切り）と入力する, Then 「AI」と「入門」の両方を含むコースだけが表示される
- **AC1.2.3** Given コース一覧が表示されている, When 全角の「ＡＩ」や小文字の「ai」で入力する, Then 「AI」と入力したときと同じ結果になる
- **AC1.2.4** Given キーワードを入力している, When 入力を変更する, Then 300 ms 以内に結果が更新される
- **AC1.2.5** Given キーワードを入力している, When キーワードを空にする, Then すべてのコース（ほかの条件があればその条件に合うもの）が表示される

INVEST: 他の絞り込みと独立して実装・テストできる。

### US1.3 カテゴリで絞り込む

- **ストーリー**: 遥さんとして、「技術」などのカテゴリでコースを絞り込みたい。関係のない分野の研修を見なくて済むようにしたいからだ。
- **優先度**: Must Have
- **要件**: FR2.3
- **依存**: US1.1

受け入れ基準:

- **AC1.3.1** Given コース一覧が表示されている, When カテゴリ「技術」を選ぶ, Then 技術カテゴリのコースだけが表示される
- **AC1.3.2** Given カテゴリ「技術」を選んでいる, When 「すべて」を選ぶ, Then カテゴリによる絞り込みが解除される
- **AC1.3.3** Given キーワード「入門」を入力している, When カテゴリ「技術」を選ぶ, Then 両方の条件を満たすコースだけが表示される

### US1.4 空席のあるコースだけにする

- **ストーリー**: 遥さんとして、空席のある日程があるコースだけを表示したい。満席で申し込めないコースを開いてがっかりしたくないからだ。
- **優先度**: Must Have
- **要件**: FR2.4
- **依存**: US1.1

受け入れ基準:

- **AC1.4.1** Given すべての日程が満席のコースと、空席のある日程を持つコースがある, When 「空席ありのみ」を選ぶ, Then 空席のある日程を持つコースだけが表示される
- **AC1.4.2** Given 開催日時を過ぎた日程にだけ空席が残っているコースがある, When 「空席ありのみ」を選ぶ, Then そのコースは表示されない
- **AC1.4.3** Given 「空席ありのみ」を選んでいる, When 選択を解除する, Then 満席のコースも含めて表示される

### US1.5 行ける期間で絞り込む

- **ストーリー**: 遥さんとして、自分が受講できる期間（例: 来月の前半）を指定してコースを絞り込みたい。繁忙期を避けて受けられるコースだけを比べたいからだ。
- **優先度**: Must Have
- **要件**: FR2.5
- **依存**: US1.1

受け入れ基準:

- **AC1.5.1** Given コース一覧が表示されている, When 開始日と終了日を指定する, Then 指定した期間内に空席のある日程を 1 つ以上持つコースだけが表示される
- **AC1.5.2** Given 期間の開始日と終了日に同じ日を指定した, When 一覧が更新される, Then その日に開催される空席のある日程を持つコースが表示される（期間の両端の日を含む）
- **AC1.5.3** Given 終了日が開始日より前になるよう入力した, When 一覧を更新しようとする, Then 期間の指定が正しくないことが入力欄の近くに表示され、一覧はそれまでの条件のまま表示される
- **AC1.5.4** Given 開始日だけを指定した, When 一覧が更新される, Then 開始日以降に空席のある日程を持つコースが表示される

### US1.6 開催日の近い順に並べる

- **ストーリー**: 遥さんとして、コースを開催日の近い順に並べたい。早く受けられる研修から検討したいからだ。
- **優先度**: Must Have
- **要件**: FR2.6
- **依存**: US1.1

受け入れ基準:

- **AC1.6.1** Given コース一覧が表示されている, When 「開催日が近い順」を選ぶ, Then 直近の開催日が早いコースから順に表示される
- **AC1.6.2** Given 直近の開催日が同じコースが複数ある, When 「開催日が近い順」で表示する, Then それらはコース ID の昇順で並び、何度表示しても同じ順になる
- **AC1.6.3** Given 今後の開催日程を持たないコースがある, When 「開催日が近い順」で表示する, Then そのコースは一覧の最後に並ぶ

### US1.7 受講料・コース名で並べる

- **ストーリー**: 遥さんとして、受講料の安い順・高い順、コース名順にも並べ替えたい。予算に合うコースを比べたり、名前で探し直したりしたいからだ。
- **優先度**: Should Have
- **要件**: FR2.6
- **依存**: US1.6（並べ替えの仕組みを共有する）

受け入れ基準:

- **AC1.7.1** Given コース一覧が表示されている, When 「受講料の安い順」を選ぶ, Then 受講料の昇順で表示される
- **AC1.7.2** Given コース一覧が表示されている, When 「受講料の高い順」を選ぶ, Then 受講料の降順で表示される
- **AC1.7.3** Given コース一覧が表示されている, When 「コース名順」を選ぶ, Then コース名の順で表示される
- **AC1.7.4** Given 受講料が同じコースが複数ある, When 受講料順で表示する, Then それらはコース ID の昇順で並ぶ

### US1.8 探した条件を URL で残す

- **ストーリー**: 遥さんとして、絞り込んだ結果の URL をブックマークしたり同僚に送ったりしたい。同じ条件で探し直す手間を省きたいからだ。
- **優先度**: Must Have
- **要件**: FR2.8
- **依存**: US1.2〜US1.6, US2.1

受け入れ基準:

- **AC1.8.1** Given キーワード・カテゴリ・空席ありのみ・期間・並べ替えを指定した, When ブラウザのアドレス欄を見る, Then それらの条件が URL に含まれている
- **AC1.8.2** Given 条件付きの URL, When その URL を新しいタブで開く, Then 同じ条件が入力欄に復元され、同じ結果が表示される
- **AC1.8.3** Given URL に存在しないカテゴリや不正な日付が含まれている, When その URL を開く, Then エラー画面にはならず、不正な条件だけが無視された状態で一覧が表示される
- **AC1.8.4** Given 一覧で条件を指定してからコースの詳細を開いた, When 一覧へ戻る, Then 指定していた条件と結果が保たれている（旧 AC2.1.3 から移動）

### US1.9 見つからないときに次の行動が分かる

- **ストーリー**: 遥さんとして、条件に合うコースがないときや一覧を読み込めなかったときに、その理由と次にできることを知りたい。行き止まりで迷いたくないからだ。
- **優先度**: Must Have
- **要件**: FR2.9, NFR4
- **依存**: US1.1

受け入れ基準:

- **AC1.9.1** Given どのコースにも一致しない条件を指定した, When 一覧が更新される, Then 「条件に合うコースがない」ことと「条件をリセット」操作が表示される
- **AC1.9.2** Given 0 件の表示が出ている, When 「条件をリセット」を操作する, Then すべての条件が解除され、すべてのコースが表示される
- **AC1.9.3** Given Web API が応答しない, When コース一覧を開く, Then 読み込みに失敗したことと「再試行」操作が表示され、0 件の表示とは区別できる
- **AC1.9.4** Given 読み込み失敗の表示が出ている, When Web API が復旧した後に「再試行」を操作する, Then コース一覧が表示される

## US2. 日程を選ぶ

### US2.1 コースの詳細を見る

- **ストーリー**: 遥さんとして、気になったコースの内容（概要、所要時間、形式、受講料）を詳しく見たい。自分に合う入門研修かどうかを判断したいからだ。
- **優先度**: Must Have
- **要件**: FR3.1, FR3.5, NFR1
- **依存**: US1.1

受け入れ基準:

- **AC2.1.1** Given コース一覧が表示されている, When コースを選ぶ, Then コース名・カテゴリ・概要・受講料・所要時間・形式（オンライン／会場）・開催日程の一覧が表示される
- **AC2.1.2** Given 存在しないコース ID の URL, When その URL を開く, Then 「コースが見つからない」ことと一覧へ戻る操作が表示される
- **AC2.1.3** （欠番）AC1.8.4 へ移動した。一覧の条件の保持は、探索条件を扱う US1.8 の振る舞いであるため

### US2.2 日程ごとの空席を確認する

- **ストーリー**: 遥さんとして、開催日程ごとの日時・形式・残席数を一度に見比べたい。自分の予定に合い、確実に申し込める日程を選びたいからだ。
- **優先度**: Must Have
- **要件**: FR3.2, FR3.3
- **依存**: US2.1

受け入れ基準:

- **AC2.2.1** Given コースの詳細を表示している, When 開催日程の一覧を見る, Then 各日程の開催日時（日本時間）・会場または形式・定員・残席数が表示されている
- **AC2.2.2** Given 残席のある日程がある, When その日程を選ぶ, Then 選んだ日程が分かる表示になり、購入確認へ進む操作が有効になる
- **AC2.2.3** Given まだ日程を選んでいない, When 画面を見る, Then 購入確認へ進む操作は無効で、日程を選ぶよう案内が表示されている

### US2.3 選べない日程の理由を知る

- **ストーリー**: 遥さんとして、選べない日程にはその理由（満席、受付終了、購入済み）を知りたい。なぜ申し込めないのかが分かれば、迷わず別の日程を探せるからだ。
- **優先度**: Must Have
- **要件**: FR3.3, FR3.4, NFR5
- **依存**: US2.2

受け入れ基準:

- **AC2.3.1** Given 残席 0 の日程がある, When コースの詳細を表示する, Then その日程は「満席」と文字で表示され、選択できない
- **AC2.3.2** Given 開催日時を過ぎた日程がある, When コースの詳細を表示する, Then その日程は「受付終了」と文字で表示され、選択できない
- **AC2.3.3** Given 遥さんがすでに購入した日程がある, When コースの詳細を表示する, Then その日程は「購入済み」と文字で表示され、選択できない
- **AC2.3.4** Given 選べない日程がある, When キーボードで日程を順に移動する, Then 選べない日程は選択されず、理由が読み上げ可能なテキストとして提供されている

## US3. 購入する

### US3.1 予算残高をいつでも確認する

- **ストーリー**: 遥さんとして、研修予算の残高をどの画面でも確認したい。予算の範囲で受けられるコースを考えながら探したいからだ。
- **優先度**: Must Have
- **要件**: FR4.1
- **依存**: なし

受け入れ基準:

- **AC3.1.1** Given 遥さんの予算残高が 60,000 pt, When 一覧・詳細・購入確認のどの画面を開いても, Then ヘッダーに「60,000 pt」と表示されている
- **AC3.1.2** Given 遥さんが 25,000 pt のコースを購入した, When 購入の完了後に一覧へ戻る, Then ヘッダーの残高が 35,000 pt に更新されている

### US3.2 購入前に購入後の残高を確認する

- **ストーリー**: 遥さんとして、購入を確定する前に、コースと日程、今の残高、受講料、購入後の残高を確認したい。予算を使いすぎないか確かめてから、安心して申し込みたいからだ。
- **優先度**: Must Have
- **要件**: FR4.2, FR4.3, FR4.4, FR5.1
- **依存**: US2.2, US3.1

受け入れ基準:

- **AC3.2.1** Given 残高 60,000 pt の遥さんが受講料 25,000 pt の日程を選んだ, When 購入確認を開く, Then コース名・開催日時・形式・受講料 25,000 pt・現在の残高 60,000 pt・購入後の残高 35,000 pt が表示される
- **AC3.2.2** Given 残高 20,000 pt の遥さんが受講料 25,000 pt の日程を選んだ, When 購入確認を開く, Then 不足額 5,000 pt が表示され、確定操作は無効になっている
- **AC3.2.3** Given 残高 25,000 pt の遥さんが受講料 25,000 pt の日程を選んだ, When 購入確認を開く, Then 購入後の残高 0 pt が表示され、確定操作は有効になっている
- **AC3.2.4** Given 購入確認を表示している, When 「日程を選び直す」を操作する, Then コースの詳細に戻り、何も購入されていない

### US3.3 購入を確定してチケットを得る

- **ストーリー**: 遥さんとして、確認した内容で購入を確定し、その日程の e チケットを受け取りたい。受講の席を確実に確保したいからだ。
- **優先度**: Must Have
- **要件**: FR5.2, FR5.3, FR5.4, FR5.5, NFR2, NFR3
- **依存**: US3.2

受け入れ基準:

- **AC3.3.1** Given 残席 3・受講料 25,000 pt の日程と、残高 60,000 pt の遥さん, When 購入を確定する, Then e チケットが 1 枚発行され、残席は 2、残高は 35,000 pt になる
- **AC3.3.2** Given 画面から送る購入要求の受講料を 1 pt に書き換えた, When Web API に送る, Then 残高からはコースのデータどおりの受講料が差し引かれる
- **AC3.3.3** Given 購入処理の途中で検証に失敗する条件（例: 残高不足）, When 購入を確定する, Then 残席・残高・チケットのいずれも変化しない
- **AC3.3.4** Given 残席 1 の日程に 2 人が同時に購入を確定した, When 処理が終わる, Then チケットは 1 枚だけ発行され、残席は 0 になり、もう 1 人は満席として拒否される

### US3.4 二重に購入されないようにする

- **ストーリー**: 遥さんとして、確定ボタンを誤って何度も押しても、購入が 1 回だけになってほしい。予算を二重に使ってしまう心配をしたくないからだ。
- **優先度**: Must Have
- **要件**: FR5.6, FR5.2
- **依存**: US3.3

受け入れ基準:

- **AC3.4.1** Given 購入確認を表示している, When 確定ボタンを素早く 2 回押す, Then 処理中は確定ボタンが無効になり、発行されるチケットは 1 枚、残高の減少も 1 回分だけである
- **AC3.4.2** Given 遥さんがある日程を購入済み, When 同じ日程の購入要求を Web API に直接送る, Then 「購入済み」として拒否され、残高と残席は変わらない
- **AC3.4.3** Given 確定の処理中, When 画面を見る, Then 処理中であることが分かる表示になっている

### US3.5 購入できなかった理由と次の行動を知る

- **ストーリー**: 遥さんとして、購入できなかったときに、その理由と次にできることを知りたい。別の日程を選ぶなど、すぐに次の手を打ちたいからだ。
- **優先度**: Must Have
- **要件**: FR5.7, FR5.8, NFR4
- **依存**: US3.3

受け入れ基準:

- **AC3.5.1** Given 購入確認を開いている間に、別の従業員が最後の 1 席を購入した, When 遥さんが確定する, Then 「この日程は満席になりました」という趣旨のメッセージと「別の日程を選ぶ」操作が表示され、残高は変わらない
- **AC3.5.2** Given 購入確認を開いている間に開催日時を過ぎた, When 確定する, Then 「受付終了」の趣旨のメッセージと「別の日程を選ぶ」操作が表示される
- **AC3.5.3** Given 確定時に Web API と通信できなかった, When 結果を待つ, Then 通信に失敗したことと「もう一度試す」操作が表示され、購入できたかどうかはコースの詳細の日程の表示（「購入済み」かどうか。AC2.3.3）で確認できることが案内される
- **AC3.5.4** Given 購入が拒否された, When 「別の日程を選ぶ」を操作する, Then 最新の残席が反映されたコースの詳細が表示される

## US4. チケットを確認する

### US4.1 購入直後にチケットを確認する

- **ストーリー**: 遥さんとして、購入が終わったらすぐに e チケットの内容を確認したい。申し込みが正しく完了したことを確かめ、受講日を予定に入れたいからだ。
- **優先度**: Must Have
- **要件**: FR6.1, FR6.2
- **依存**: US3.3

受け入れ基準:

- **AC4.1.1** Given 購入が成功した, When 完了画面が表示される, Then チケット番号・従業員名・コース名・開催日時・会場または形式・購入日時・支払ったポイントが表示される
- **AC4.1.2** Given 2 枚のチケットを購入した, When それぞれのチケット番号を見る, Then 2 つの番号は異なる
- **AC4.1.3** Given 完了画面を表示している, When 「コース一覧へ戻る」を操作する, Then コース一覧が表示され、ヘッダーの残高が購入後の値になっている（「購入済みチケットを見る」への移動は AC4.2.4 へ移動）

### US4.2 購入済みチケットを見返す

- **ストーリー**: 遥さんとして、これまでに購入した e チケットを一覧で見返したい。受講日が近づいたときに、日時や形式をすぐ確認したいからだ。
- **優先度**: Must Have
- **要件**: FR6.3
- **依存**: US4.1

受け入れ基準:

- **AC4.2.1** Given 2 枚購入済みの遥さん, When 購入済みチケットの一覧を開く, Then 2 枚が開催日時の近い順に表示される
- **AC4.2.2** Given 購入済みのチケットがない, When 一覧を開く, Then チケットがないことと、コース一覧へ移動する操作が表示される
- **AC4.2.3** Given 一覧のチケットを選ぶ, When 詳細を表示する, Then 完了画面と同じ項目（AC4.1.1）が表示される
- **AC4.2.4** Given 購入の完了画面を表示している, When 「購入済みチケットを見る」を操作する, Then 購入済みチケットの一覧が表示され、いま購入したチケットが含まれている（旧 AC4.1.3 の一部から移動）
- **AC4.2.5** Given どの画面を表示していても, When ヘッダーの「購入済みチケット」を操作する, Then 操作中の従業員の購入済みチケットの一覧が表示される

## US5. 利用資格

### US5.1 契約外の企業では購入できないと分かる

- **ストーリー**: 遥さんとして、異動や出向で所属する企業がサービスの契約外になった場合には、購入できないことを申し込みの途中ではなく早い段階で知りたい。無駄な操作をせず、社内の担当窓口に相談できるようにしたいからだ。
- **優先度**: Must Have
- **要件**: FR1.3, FR1.4, NFR3
- **依存**: US3.2

受け入れ基準:

- **AC5.1.1** Given 契約が終了した企業の従業員として利用している, When コースの一覧や詳細を見る, Then 閲覧はできるが「ご所属の企業は現在このサービスをご利用いただけません」という趣旨の案内が表示されている
- **AC5.1.2** Given 契約が終了した企業の従業員として利用している, When 購入確認を開く, Then 確定操作は無効になっている
- **AC5.1.3** Given 契約が終了した企業の従業員の ID で, When Web API に購入要求を直接送る, Then 要求は拒否され、残高と残席は変わらない
- **AC5.1.4** Given 存在しない従業員 ID で, When Web API に購入要求を送る, Then 要求は拒否される

## INVEST の確認

| 観点 | 確認結果 |
| --- | --- |
| Independent（独立） | 各ストーリーは 1 つの振る舞いに絞った。依存は「依存」欄に明記し、循環する依存はない |
| Negotiable（交渉可能） | 画面の部品（チップ、ドロップダウンなど）は指定せず、利用者がしたいことで書いた |
| Valuable（価値） | すべて遥さんの目的・困りごと（`personas.md`）に結び付く「なぜなら」を書いた |
| Estimable（見積もり可能） | 振る舞いと受け入れ基準が具体的で、規模を見積もれる |
| Small（小さい） | 1 ストーリーの受け入れ基準は 2〜5 件に収めた |
| Testable（テスト可能） | 受け入れ基準はすべて Given/When/Then で、合否を判定できる |

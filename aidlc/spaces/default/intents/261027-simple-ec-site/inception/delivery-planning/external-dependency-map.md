# 外部依存マップ

**Bolt**（ボルト）は、1 つ以上のユニットを設計からコードまで 1 回通して、実際に動くものを仕上げる作業のまとまりを指す。この文書は、チームの外側にあって Bolt を止める可能性のあるものと、それを使う Bolt の対応を示す。

`delivery-planning-questions.md` Q4 では「外部の要因はない」との回答だった。その後、開発環境のツールの取得を確認したところ、次の 1 件が見つかったため記録する。

| ID | 外部の要因 | 担当 | かかる時間 | 止める Bolt | 遅れた場合の対応 |
| --- | --- | --- | --- | --- | --- |
| ED-1 | MoonBit のツール（コンパイラとパッケージ）の取得先が、このクラウド開発環境のネットワーク設定でブロックされている。ブロックされているホスト: `cli.moonbitlang.com`（インストーラー）、`download.moonbitlang.com`（ツール本体）、`mooncakes.io`（パッケージ置き場） | 利用者（環境の設定変更） | 設定変更のみ（数分） | Bolt 1 の画面部分（以降の Bolt 2・Bolt 3 の画面部分も） | 許可されるまでは、Rust 側（業務ロジック・Web API・データストア）の実装とテストを先に進める。画面部分は許可後に作る |

### ED-1 の解除手順

セッションのタイトルバーにあるクラウド環境のメニューから「Edit」を開き、「Network access」で上記 3 つのホストを「Allowed domains」に追加する（「Allow package managers」のチェックは付けたまま）。手順の詳細: https://code.claude.com/docs/en/cloud-environments#network-access

## 依存しないことを確認したもの

| 対象 | 状態 |
| --- | --- |
| Rust のツールチェーン | 導入済み（rustc / cargo 1.97.0） |
| Rust の crate の取得（`index.crates.io`） | 接続できる |
| 外部 API・外部データ・他チームの承認 | なし（ローカル検証のみ。データはメモリ上の初期データ） |

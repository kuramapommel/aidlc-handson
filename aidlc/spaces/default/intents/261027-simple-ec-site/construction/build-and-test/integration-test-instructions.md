# 結合テストの手順

テストの方針は Minimal（`aidlc-state.md` の Test Strategy）のため、新しい結合テストは作らない。ユニットをまたぐ結合は、次の既存のテストと、この工程で行ったブラウザでの確認で確かめる。

## 既存のテストでの確認（自動）

Web API のテストは、サーバーを起動せず、本物のメモリのデータストアを固定の時刻で組み立てて呼ぶ（業務の部品・データストア・Web API の結合）。

```bash
cargo test -p web_api            # api・search・my_tickets・performance など
```

ユニットをまたぐ流れの例: 購入（U1）のあとに購入済みチケットの一覧（U3）を引くと、いま購入したチケットが含まれる（`crates/web_api/tests/my_tickets.rs`）。

## ブラウザでの確認（2 プロセスを起動して行う）

1. `cargo run -p web_api` と `cargo run -p static_server` を起動する（`RUST_LOG=debug` でログの詳しさも確かめる）。
2. Playwright（この環境に入っている Chromium）で、README の「デモの手順」の流れを操作する: 一覧 → 探索（キーワード・カテゴリ・URL の復元）→ 詳細と日程 → 購入確認 → 確定 → 完了 → 購入済みチケット（開閉）→ 従業員の切り替え → チケットのない従業員の案内。キーボードだけの購入、選べない日程、ラベル、ライブリージョンも確かめる。
3. Web API を止めた状態で画面を開き、読み込み失敗の表示と「再試行」を確かめる。
4. Web API のログ（1 行の要求ログ、拒否の理由、400 の項目名、ログに内容が出ないこと）を確かめる。

結果は `test-results.md` に書く。確認に使ったスクリプトはリポジトリには含めない（Minimal のため。必要になったら E2E テストとして追加を検討する）。

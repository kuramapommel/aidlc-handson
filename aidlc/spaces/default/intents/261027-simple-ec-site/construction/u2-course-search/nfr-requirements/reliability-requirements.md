# 信頼性と品質の保ち方の要件（U2 コース探索）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR2（信頼性・整合性）・NFR6（実装スタイル）・NFR8（テスト容易性）・NFR9（実行容易性）を、U2 に当てはめる。U1 の要件（`../../u1-purchase-skeleton/nfr-requirements/reliability-requirements.md`）はそのまま引き継ぐ。

## 整合性（NFR2）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR2.1 | 探索はデータを書き換えない。探索の受け口を何回呼んでも、残席・残高・チケットは変わらない | Web API の自動テスト |
| NFR2.2 | 入力中に連続して送った探索の応答が順不同で届いても、表示は最後に送った条件の結果になる（BR11.2） | 画面の更新関数の自動テスト（古い番号の応答を後から届けても捨てられる） |
| NFR2.3 | 探索の失敗（通信の失敗・5xx・400）で画面が操作不能にならない。失敗の表示と「再試行」、または一覧を保った案内を出す（BR11.7、BR11.9） | 画面の更新関数の自動テスト |

## 実装スタイル（NFR6）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR6.1 | 条件の検証・キーワードの正規化・絞り込み・並べ替えは純粋関数で書く。現在時刻は引数で受け取る | コードレビュー |
| NFR6.2 | キーワードの入力の待ち（150 ms）は、画面の更新関数が「待ちのコマンド」を返し、待ち終わりのメッセージの番号で最新かを判断する形にする。更新関数の中で時計やタイマーを直接使わない | コードレビュー、画面の自動テスト |
| NFR6.3 | 並べ替えの比較は、どの並べ方でも最後にコース ID で比べ、毎回同じ順になる（安定した全順序） | 自動テスト |

## テスト容易性（NFR8）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR8.1 | Rust の探索のテストは `cargo test` で、画面の探索のテストは `moon -C web test --target js` で、手作業の準備なしに実行できる（U1 と同じ。画面のテストには Node.js を使う） | テストの実行 |
| NFR8.2 | 受け入れ基準（AC1.2.1〜AC1.9.4）の振る舞いを、Web API のテスト（絞り込み・並べ替え・件数・400）と画面の更新関数のテスト（待ち・古い応答・URL の復元・0 件・失敗・期間の案内）で確かめる。各部品は成功の場合に加えて 2 つ以上の失敗・境目の場合を持つ | テストのレビュー |
| NFR8.3 | 時刻に依存する探索のテスト（今後の日程、期間）は固定の時刻で行う | テストのレビュー |

## 実行容易性（NFR9）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR9.1 | U2 で前提のツールを増やさない。Construction の確認コマンド（`bash scripts/verify.sh`）で U2 のテストも実行される | 確認コマンドの実行 |

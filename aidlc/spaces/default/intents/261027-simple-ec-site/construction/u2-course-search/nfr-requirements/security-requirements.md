# セキュリティの要件（U2 コース探索）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR3（セキュリティ）を、U2 の探索に当てはめて具体化する。U1 の要件（`../../u1-purchase-skeleton/nfr-requirements/security-requirements.md`。Cookie・CSRF 対策・CORS など）はそのまま引き継ぐ。探索は読み出しだけで、データを変えない。この工程の決定のまとめは `nfr-requirements-questions.md` で確認済み（2026-10-30）。

## 前提（脅威の範囲）

- 探索の受け口（`GET /api/courses`）は閲覧の要求で、契約状態にかかわらず誰でも使える（U1 の BR1.2）。
- 想定する攻撃: 不正な条件の直接送信、極端に長いキーワード、キーワードへの HTML・スクリプトの埋め込み、URL のクエリの改ざん。

## 要件

| ID | 要件 | 関係するルール | 確かめ方 |
| --- | --- | --- | --- |
| NFR3.1 | 形の決まった条件（カテゴリ・空席ありのみ・開始日・終了日・期間の前後・並べ替え）は、Web API がすべて検証し、不正なら 400 と不正な条件の一覧を返す。結果は返さない | BR8.2〜BR8.6 | Web API の自動テスト |
| NFR3.2 | キーワードは自由入力として拒否しない。ただし探索に使うのは先頭 200 文字までとし、それより長い部分は捨てる。キーワードの長さで処理の時間が大きく伸びないようにする | BR8.1 | Web API の自動テスト（数万文字のキーワードでも 200 ms 以内に応答する） |
| NFR3.3 | キーワードは文字列の一致だけで照合し、正規表現やほかの命令として解釈しない | BR9.1 | コードレビュー |
| NFR3.4 | 画面は、キーワード・コース名・概要など Web API から受け取った文字列も、利用者が入力した文字列も、文字として表示し、HTML として解釈させない（U1 の NFR3.11 を探索の表示にも当てはめる） | — | コードレビュー、`<script>` を含むキーワードでの目視 |
| NFR3.5 | URL のクエリの値は、画面が項目ごとに検証してから使う。不正な値は無視し、そのまま Web API に送らない | BR11.4 | 画面の自動テスト |
| NFR3.6 | 400 の応答に含めるのは、不正な条件の項目名と短い理由だけにし、受け取った値そのものや内部の情報は返さない | BR8.6 | Web API の自動テスト |

## 対象外

- 探索の回数の制限（レート制限）は、ローカル検証のため扱わない（U1 と同じ）。

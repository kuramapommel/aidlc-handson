# 性能・操作性の要件（U2 コース探索）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR1（性能）・NFR4（ユーザビリティ）・NFR5（アクセシビリティ）を、U2 の探索に当てはめて具体化する。U1 の要件（`../../u1-purchase-skeleton/nfr-requirements/performance-requirements.md`）はそのまま引き継ぎ、ここでは U2 で足すものだけを書く。

前提: U1 と同じくローカル環境・初期データの規模で測る。

## 性能の目標

| ID | 対象 | 目標 | 測り方 |
| --- | --- | --- | --- |
| NFR1.1 | 探索条件付きのコース一覧（`GET /api/courses`。キーワード・カテゴリ・空席ありのみ・期間・並べ替えの組み合わせ） | 95% の要求が 200 ms 以内に応答する | Web API の自動テストで、条件の組み合わせを替えながら 100 回送り、95 パーセンタイルを確かめる |
| NFR1.2 | 条件を変えてから一覧に反映するまで（画面） | キーワードは入力が止まってから、ほかの条件は変えてから 300 ms 以内に表示へ反映する（キーワードの 150 ms の待ちを含む。BR11.1） | 待ちの時間（150 ms）を更新関数のテストで確かめ、ブラウザで目視する |
| NFR1.3 | 画面の再描画 | 条件を変えても全画面を読み込み直さず、探索条件の入力欄の値・入力中の文字の位置を保つ | ブラウザで目視 |

## 操作性の目標

| ID | 目標 | 確かめ方 |
| --- | --- | --- |
| NFR4.1 | 読み込み中・0 件・読み込み失敗の 3 つを、文言の違う別の表示にする（BR11.6、BR11.7） | 画面の更新関数と描画の自動テスト、目視 |
| NFR4.2 | 0 件では「条件をリセット」、失敗では「再試行」を必ず出す | 画面の自動テスト |
| NFR4.3 | 期間の前後が逆のとき、入力欄の近くに案内を出し、一覧はそれまでのまま（BR11.5） | 画面の自動テスト |
| NFR4.4 | 詳細から一覧へ戻ったとき、条件と結果が保たれる（BR11.8） | ブラウザで目視 |

## アクセシビリティの目標（基本）

| ID | 目標 | 確かめ方 |
| --- | --- | --- |
| NFR5.1 | 探索条件のすべての入力（キーワード・カテゴリ・空席ありのみ・開始日・終了日・並べ替え）と「条件をリセット」「再試行」を、キーボードだけで操作できる | 手動確認 |
| NFR5.2 | すべての入力にラベルがある | 手動確認 |
| NFR5.3 | 件数の変化と、0 件・失敗・期間の案内を、読み上げ可能な文字で伝える（ライブリージョンと、入力欄に結び付けた説明） | 手動確認 |

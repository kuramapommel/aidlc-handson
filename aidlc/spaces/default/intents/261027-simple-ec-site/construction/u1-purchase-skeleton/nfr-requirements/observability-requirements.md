# 可観測性の要件（U1 購入の最小の流れ）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR10（可観測性（最小））を、U1 の Web API に当てはめて具体化する。ローカル検証専用のため、監視の仕組み・ダッシュボード・アラート・分散トレースは作らない（要件「6. 対象外」）。ログは標準出力に出し、開発者が目で見て確かめる。

## 要件

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR10.1 | Web API は、要求ごとに 1 行のログを出す。項目はメソッド・パス・状態コード・処理時間（ミリ秒）とする | Web API を起動して目視 |
| NFR10.2 | 購入の拒否は、従業員 ID・日程 ID・拒否の理由（BR5.1 の 7 つのどれか）をログに出す（BR5.8）。承認した購入は、チケット ID・従業員 ID・日程 ID をログに出す | 目視と、拒否の各理由を起こす操作 |
| NFR10.3 | ログに個人の連絡先は出さない（今回は扱わない）。従業員の表示名もログに出さず、従業員 ID だけを出す | コードレビュー |
| NFR10.4 | ログは人が読める 1 行の形式で出す。ログの詳しさは環境変数で変えられる（既定は情報レベル。開発中は詳細レベルにできる） | 起動時の設定を変えて目視 |
| NFR10.5 | 予期しない失敗は、エラーの内容をログに出す（応答には出さない。security-requirements.md NFR3.10） | コードレビュー |
| NFR10.6 | 起動時に、Web API と画面用の静的ファイルサーバーが待ち受けるアドレス（例: `http://localhost:3000`、`http://localhost:8080`）と、許可した画面のオリジンをログに出す | 起動して目視 |
| NFR10.7 | Web API は、動作確認用に `GET /api/health` を持ち、動いていれば 200 を返す。確認コマンドや手動の確認で使う | Web API の自動テスト |

## 指標（SLI）について

稼働率や応答時間の指標を継続して集める仕組みは作らない。応答時間の目標（performance-requirements.md NFR1.1〜NFR1.3）は、自動テストの中で測って確かめる。

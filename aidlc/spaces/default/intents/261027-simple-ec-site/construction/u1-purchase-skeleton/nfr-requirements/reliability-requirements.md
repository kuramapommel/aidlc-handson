# 信頼性と品質の保ち方の要件（U1 購入の最小の流れ）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR2（信頼性・整合性）に加え、品質を保つための NFR6（実装スタイル）・NFR8（テスト容易性）・NFR9（実行容易性）を、U1 に当てはめて具体化する。

## 前提

- データはメモリ上にあり、Web API を再起動すると初期データに戻る（要件 A5）。バックアップと復旧は扱わない。
- 稼働率の目標（SLO）は置かない。ローカル検証専用で、常時動かすサービスではないため（要件 C1）。

## 整合性（NFR2）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR2.1 | 予算の残高と残席数は負の値にならない。購入は「チケット 1 枚と消費の取引 1 件をどちらも反映する」か「何も反映しない」かのどちらかで、一部だけを反映した状態を残さない（BR5.3） | 業務の部品とデータストアの自動テスト（拒否の各理由で、残高・残席・チケットが変わらないこと） |
| NFR2.2 | 残席 1 の日程に同時に 2 件の購入が届いても、チケットは 1 枚だけ発行され、もう 1 件は満席として拒否される（BR5.4、AC3.3.4） | データストアに対して複数のタスクから同時に購入を送る自動テスト。同時に送る件数を定員より多くして（例: 定員 3 に 20 件）、発行数が定員を超えないことも確かめる |
| NFR2.4 | 同じ従業員の同じ日程への購入が重ねて届いても、チケットは 1 枚だけ発行される（BR5.5、AC3.4.1、AC3.4.2） | 同じ要求を同時に複数送る自動テスト |
| NFR2.5 | Web API の処理中に予期しない失敗が起きても、データストアの状態は変わらず、プロセスは次の要求を受け付け続ける（1 件の失敗でサーバー全体を止めない） | Web API の自動テストとコードレビュー |
| NFR2.6 | 画面は、Web API と通信できないときも操作不能にならない。一覧・詳細では失敗の表示と「再試行」、購入では「もう一度試す」と確かめ方の案内を出す（BR7.1、BR7.6） | 画面の更新関数の自動テスト、Web API を止めた状態での目視 |

## 実装スタイル（NFR6）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR6.1 | 業務の部品は純粋関数で書く。現在時刻と乱数は引数（関数）として受け取り、業務の部品の中で時計や乱数を直接呼ばない | コードレビュー |
| NFR6.2 | データは不変として扱う。状態の更新は「現在の状態 → 新しい状態」を返す関数で表し、可変な内部状態を持つオブジェクトやクラス階層による設計をしない。可変な共有状態は、データストアの「現在の状態を置き換える 1 か所」だけに閉じ込める | コードレビュー |
| NFR6.3 | 部品の組み立ては、関数の部分適用（クロージャ）で行う。依存の逆転にインターフェース（トレイトのオブジェクト）を使わず、関数を受け渡す（project.md の決定） | コードレビュー |
| NFR6.4 | 画面は TEA（ADR-007）で組み、更新関数と描画関数は純粋関数にする。Web API の呼び出し・URL の書き換えはコマンドとして外に出す | コードレビュー |

## テスト容易性（NFR8）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR8.1 | Rust のテストは、リポジトリのルートからの `cargo test` 1 回で、手作業の準備なしにすべて実行できる（Web API のテストもサーバーを別に起動せずに動く） | `cargo test` の実行 |
| NFR8.2 | MoonBit のテストは、リポジトリのルートからの `moon -C web test --target js` で、手作業の準備なしに実行できる（Node.js が必要。NFR9.1）。更新関数（メッセージ＋状態 → 新しい状態＋コマンド）の振る舞いをテストする | `moon test` の実行 |
| NFR8.3 | 業務の部品のテストは、成功の場合に加えて、少なくとも 2 つの失敗・境目の場合を持つ（例: 購入の決定なら、残高ちょうど・残高不足・満席・受付終了・購入済み・契約外・存在しない従業員・存在しない日程） | テストのレビュー |
| NFR8.4 | 時刻に依存するテスト（受付終了、初期データの日程）は、固定した時刻を渡して結果が毎回同じになるようにする | テストのレビュー |

## 実行容易性（NFR9）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR9.1 | ビルドと起動の前提のツールは Rust（最新 stable）と MoonBit（最新版）だけとする。画面用の静的ファイルサーバーは Rust のワークスペースの実行ファイルで用意する（Q2）。画面のテスト（`moon -C web test --target js`）の実行にだけ Node.js を使う（MoonBit が JavaScript 向けのテストを Node.js で動かすため。2026-10-29 に利用者が承認） | README の手順どおりに起動 |
| NFR9.2 | リポジトリのルートからのコマンドで、ビルド・テスト・2 プロセスの起動ができる。手順は README に書く | README の手順どおりに起動 |
| NFR9.3 | Construction の確認コマンド（`bash scripts/verify.sh`）は、Rust のテスト・MoonBit のテスト・画面のビルドを順に実行し、どれかが失敗すれば失敗で終わる。MoonBit のツールがない場合は、その旨を表示して失敗で終わる（成功と偽らない） | 確認コマンドの実行 |

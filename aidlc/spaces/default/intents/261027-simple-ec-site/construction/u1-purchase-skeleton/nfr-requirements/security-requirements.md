# セキュリティの要件（U1 購入の最小の流れ）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR3（セキュリティ）を、U1 の Web API と画面に当てはめて具体化する。機能設計の業務ルール（`../functional-design/rules.md`）の BR 番号を併記する。

## 前提（脅威の範囲）

- **ローカル検証専用**である（要件 C1）。ログイン機能は作らず、Cookie に入った従業員 ID を認証済みとして扱う（ADR-008、BR6.1）。従業員 ID を偽れば他人として操作できるため、**公開された環境に置いてはならない**。
- 守るもの: 予算の残高と残席の整合性、購入の可否と金額の判断、ほかの従業員のチケットの内容。
- 想定する攻撃: 画面を通さない Web API の直接呼び出し、要求の改ざん（金額・従業員 ID・日程 ID）、別のサイトからのなりすまし送信（CSRF）、二重送信。
- 個人の連絡先（メールアドレス・電話番号）は扱わない。

## 要件

| ID | 要件 | 関係するルール | 確かめ方 |
| --- | --- | --- | --- |
| NFR3.1 | Web API は、すべての入力を検証する。ID の形式（コース ID は C と 3 桁の数字、日程 ID は S と 4 桁の数字、従業員 ID は E と 3 桁の数字、チケット ID は内部の識別子の形式）に合わない要求は 400、本文の JSON が読めない要求も 400 で応答する | — | Web API の自動テスト |
| NFR3.2 | 購入の可否は Web API が最終的に判断し、画面の表示（ボタンの無効化など）に頼らない。最終チェックの順と理由は BR5.1 のとおり | BR1.1、BR5.1 | Web API の自動テスト（画面を通さずに満席・受付終了・購入済み・残高不足・契約外の要求を送る） |
| NFR3.3 | 受講料はコースのデータから決め、要求の本文に金額があっても読み取らない | BR5.2 | 金額を含めた要求を送る自動テスト（AC3.3.2） |
| NFR3.4 | 操作中の従業員 ID の Cookie は、画面のスクリプトから読めない設定（HttpOnly）、同じサイトの中だけで送る設定（SameSite=Lax）、パスは `/` とする。ローカルの http で動かすため、https だけで送る設定（Secure）は付けない（公開しないことの前提。NFR3.8） | BR6.1、BR6.2 | Web API の自動テストで応答の Cookie の属性を確かめる |
| NFR3.5 | 書き込みの要求（購入・従業員の切り替え）は、送信元（Origin ヘッダー）が許可した画面のオリジンであり、かつ画面だけが付ける専用のヘッダー（例: `X-Requested-With: aidlc-handson-web`）が付いている場合だけ受け付ける。満たさない要求は 403 で拒否し、何も変えない | BR6.3 | Web API の自動テスト（Origin なし・別の Origin・専用ヘッダーなし） |
| NFR3.6 | オリジンをまたぐ通信（CORS）は、画面のオリジン（既定は `http://localhost:8080`。設定で変えられる）だけに、資格情報（Cookie）付きで許可する。ワイルドカード（すべてのオリジン）は使わない | BR6.3 | Web API の自動テスト（許可しないオリジンからのプリフライト） |
| NFR3.7 | チケット 1 枚の詳細は、そのチケットを購入した従業員にだけ返す。ほかの従業員のチケットには、存在しない場合と同じ 404 を返す（存在するかどうかも漏らさない） | BR5.10 | Web API の自動テスト |
| NFR3.8 | Cookie の従業員 ID を認証済みとして扱うのはローカル検証専用であることを、README と、Cookie を読み取るコードのコメントに明記する | ADR-008 | コードレビュー |
| NFR3.9 | 秘密情報（パスワード・API キーなど）をコードに埋め込まない。今回は秘密情報を使わない。設定値（ポート、画面のオリジン）は環境変数で変えられるようにし、既定値をコードに持つ | — | コードレビュー |
| NFR3.10 | 予期しない失敗では 5xx と一般的なメッセージだけを返し、内部の情報（スタックトレース・内部の状態）を応答に含めない。詳細はログにだけ出す | — | Web API の自動テストとコードレビュー |
| NFR3.11 | 画面は、Web API から受け取った文字列（コース名・説明など）をそのまま HTML として解釈させず、文字として表示する（スクリプトの埋め込みを防ぐ） | — | コードレビュー（画面の描画は仮想 DOM のテキストとして渡す） |

## 対象外

- 認証（ログイン・ログアウト）、通信の暗号化（https）、レート制限は、ローカル検証のため扱わない（要件「6. 対象外」）。将来、社内ポータルの認証につなぐときは、Cookie に従業員 ID を直接入れる形をやめ、ポータルが発行するセッションから従業員 ID を取り出す処理に差し替える（ADR-008）。

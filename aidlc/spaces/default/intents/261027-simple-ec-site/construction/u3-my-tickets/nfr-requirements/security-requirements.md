# セキュリティの要件（U3 購入済みチケット）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR3（セキュリティ）を、U3 の購入済みチケットに当てはめて具体化する。U1 の要件（`../../u1-purchase-skeleton/nfr-requirements/security-requirements.md`。Cookie・CSRF 対策・CORS・文字としての表示など）はそのまま引き継ぐ。一覧は読み出しだけで、データを変えない。この工程の決定のまとめは `nfr-requirements-questions.md` で確認済み（2026-11-03）。

## 前提（脅威の範囲）

- ローカル検証専用で、ログインはない。Cookie の従業員 ID をそのまま操作中の従業員として扱う（ADR-008）。Cookie を書き換えれば他人として見られることは、U1 と同じく前提として受け入れる。
- 想定する攻撃: 他人のチケットを一覧で引き出そうとする要求（クエリや本文での従業員の指定）、存在しない従業員 ID の Cookie、コース名などへの HTML・スクリプトの埋め込み。

## 要件

| ID | 要件 | 関係するルール | 確かめ方 |
| --- | --- | --- | --- |
| NFR3.1 | 一覧は Cookie の操作中の従業員のチケットだけを返す。クエリや本文で従業員を指定する手段は設けず、付けられても無視する | BR12.1、BR13.1 | Web API の自動テスト（他の従業員のチケットが含まれない。クエリに従業員 ID を付けても結果が変わらない） |
| NFR3.2 | Cookie の従業員 ID が存在しない従業員を指すときは、空の一覧を返し、ほかの従業員のチケットや内部の情報を返さない | BR12.1 | Web API の自動テスト |
| NFR3.3 | 一覧は読み出しの要求なので、U1 の CSRF 対策（BR6.3）の対象外とする。書き込みの受け口は U3 で増やさない | — | コードレビュー |
| NFR3.4 | 画面は、コース名・会場・従業員名など Web API から受け取った文字列を文字として表示し、HTML として解釈させない（U1 の NFR3.11 を一覧にも当てはめる） | — | コードレビュー |
| NFR3.5 | 従業員を切り替えたら、前の従業員のチケットを画面に残さない | BR14.8 | 画面の更新関数の自動テスト |

## 対象外

- 一覧の要求の回数の制限（レート制限）は、ローカル検証のため扱わない（U1 と同じ）。

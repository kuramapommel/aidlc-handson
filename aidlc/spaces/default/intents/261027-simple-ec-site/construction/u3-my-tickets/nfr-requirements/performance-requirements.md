# 性能・操作性の要件（U3 購入済みチケット）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR1（性能）・NFR4（ユーザビリティ）・NFR5（アクセシビリティ）を、U3 の購入済みチケットに当てはめて具体化する。U1 の要件（`../../u1-purchase-skeleton/nfr-requirements/performance-requirements.md`）はそのまま引き継ぎ、ここでは U3 で足すものだけを書く。

前提: U1 と同じくローカル環境・初期データの規模で測る。この工程の決定のまとめは `nfr-requirements-questions.md` で確認済み（2026-11-03）。

## 性能の目標

| ID | 対象 | 目標 | 測り方 |
| --- | --- | --- | --- |
| NFR1.1 | 購入済みチケットの一覧（`GET /api/tickets`） | 初期データの規模で、95% の要求が 200 ms 以内に応答する（NFR1 はコース一覧・詳細の目標だが、U3 の読み出しにも同じ目標を当てる） | Web API の自動テストで 100 回送り、95 パーセンタイルを確かめる |
| NFR1.2 | 一覧のチケットを開く（BR14.4） | 通信せず、操作した直後の再描画で詳細を表示する（BR13.2） | 画面の更新関数のテスト（開閉のメッセージがコマンドを返さない）、目視 |

## 操作性の目標

| ID | 目標 | 確かめ方 |
| --- | --- | --- |
| NFR4.1 | 一覧の読み込み中・0 件・読み込み失敗の 3 つを、文言の違う別の表示にする（BR14.2・BR14.3） | 画面の描画の自動テスト、目視 |
| NFR4.2 | 0 件では「コース一覧へ」、失敗では「再試行」を必ず出す | 画面の自動テスト |
| NFR4.3 | ヘッダーの「購入済みチケット」と、完了画面の「購入済みチケットを見る」から、1 回の操作で一覧へ移れる（BR14.6・BR14.7） | 画面の自動テスト、目視 |

## アクセシビリティの目標（基本）

| ID | 目標 | 確かめ方 |
| --- | --- | --- |
| NFR5.1 | ヘッダーのリンク・完了画面のリンク・開閉のボタン・「再試行」・「コース一覧へ」を、キーボードだけで操作できる | 手動確認 |
| NFR5.2 | 開閉のボタンに名前（「詳細を見る」「詳細を閉じる」）を付け、開いているかどうかを支援技術に伝える（BR14.4） | 描画の自動テスト（属性の確認）、手動確認 |
| NFR5.3 | 「受講済み」を色だけでなく文字で示す（BR14.5） | 描画の自動テスト |

# 信頼性と品質の保ち方の要件（U3 購入済みチケット）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR2（信頼性・整合性）・NFR6（実装スタイル）・NFR8（テスト容易性）・NFR9（実行容易性）を、U3 に当てはめる。U1 の要件（`../../u1-purchase-skeleton/nfr-requirements/reliability-requirements.md`）はそのまま引き継ぐ。この工程の決定のまとめは `nfr-requirements-questions.md` で確認済み（2026-11-03）。

## 整合性（NFR2）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR2.1 | 一覧はデータを書き換えない。一覧の受け口を何回呼んでも、残席・残高・チケットは変わらない | Web API の自動テスト |
| NFR2.2 | 購入の直後に一覧を開くと、いま購入したチケットが含まれる（一覧を開くたびに読み込み直す。BR14.1） | Web API の自動テスト（購入のあと一覧を引く）、画面の更新関数の自動テスト |
| NFR2.3 | 一覧の読み込みに失敗しても画面が操作不能にならず、失敗の表示と「再試行」を出す。一覧の画面でないときに届いた応答は表示に使わない | 画面の更新関数の自動テスト |

## 実装スタイル（NFR6）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR6.1 | 一覧の絞り込み・受講済みの判定・並べは純粋関数で書く。現在時刻は引数で受け取る | コードレビュー |
| NFR6.2 | 開閉の状態は画面の Model の不変な値（開いているチケット ID の集合）で持ち、更新関数が新しい値を返す | コードレビュー、画面の自動テスト |
| NFR6.3 | 並べの比較は、開催日時・購入日時・チケット番号の順で比べ、毎回同じ順になる（安定した全順序。BR12.2） | 自動テスト |

## テスト容易性（NFR8）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR8.1 | Rust の一覧のテストは `cargo test` で、画面のテストは `moon -C web test --target js` で、手作業の準備なしに実行できる（U1・U2 と同じ） | テストの実行 |
| NFR8.2 | 受け入れ基準（AC4.2.1〜AC4.2.5）の振る舞いを、Purchasing と Web API のテスト（並び・受講済み・他人のチケットを含めない・0 件）と画面のテスト（読み込みの状態・開閉・導線・切り替えでの破棄）で確かめる。各部品は成功の場合に加えて 2 つ以上の失敗・境目の場合を持つ | テストのレビュー |
| NFR8.3 | 受講済みの判定と並びのテストは固定の時刻で行い、開始日時ちょうど・同じ開催日時・同じ購入日時の場合を含める | テストのレビュー |

## 実行容易性（NFR9）

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR9.1 | U3 で前提のツールを増やさない。Construction の確認コマンド（`bash scripts/verify.sh`）で U3 のテストも実行される | 確認コマンドの実行 |

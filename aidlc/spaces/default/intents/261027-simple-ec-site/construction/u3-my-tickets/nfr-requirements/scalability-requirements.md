# 拡張性の要件（U3 購入済みチケット）

要件定義書（`../../../inception/requirements-analysis/requirements.md`）の NFR7（データアクセスの差し替え）を、U3 の購入済みチケットに当てはめる。想定する規模は U1 と同じ（`../../u1-purchase-skeleton/nfr-requirements/scalability-requirements.md`）。この工程の決定のまとめは `nfr-requirements-questions.md` で確認済み（2026-11-03）。

## 要件

| ID | 要件 | 確かめ方 |
| --- | --- | --- |
| NFR7.1 | 一覧の絞り込み（操作中の従業員）・受講済みの判定・並べは Purchasing の純粋関数として書き、データストアに依存しない。日程・コース・従業員は引く関数として、現在時刻は値として受け取る | コードレビュー |
| NFR7.2 | 将来 PostgreSQL に移すときは、従業員 ID でチケットを引く検索（従業員 ID の索引）に置き換えられる形にし、その注意を関数のコメントに書いておく | コードレビュー |
| NFR7.3 | 一覧のテストは、データストアを使わず、固定のチケット・日程・コース・従業員を返す関数を渡して動かす | Purchasing の自動テスト |
| NFR7.4 | 画面の Route と状態は、U1・U2 の項目を変えずに足す | コードレビュー |

## 対象外

- 一覧のページ分けや絞り込みは扱わない（1 人の購入枚数は初期データと手での購入の規模にとどまるため）。
